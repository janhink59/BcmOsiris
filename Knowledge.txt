2. Databázové konvence (MSSQL)
* Databáze plně podporuje UTF-8 (zohledni to v PHP skriptech i T-SQL).
* Textové sloupce používají varchar/varchar(max), identifikátory používají typ uuid (uniqueidentifier). Názvy se píší striktně malými písmeny (snake_case).
* Změny struktur se provádí výhradně idempotentně: nové sloupce voláním EXEC p_create_missing_column, indexy voláním EXEC sp_create_index.
* Je přísně zakázáno používat destruktivní DROP TABLE IF EXISTS u tabulek pro zachování existujících dat.
* Cizí klíče (FOREIGN KEY) jsou zakázány, veškerá referenční integrita se řeší aplikačně nebo triggery. Oddělovač GO musí být vždy psán velkými písmeny.

3. Architektura RAC a SSC (Record & Access Control + Schvalovací cyklus)
* Záznamy jsou logicky identifikovány pomocí sloupce original (uuid). Primárním klíčem řádku je uuid.
* Vlastníkem (tenantem) je object_owner. Systémové záznamy mají object_owner = 0x00. Objekty vlastněné systémem nelze běžně smazat, k jejich deaktivaci slouží příznak inactive.
* Deterministický originál: Vazební tabulky a další objekty používají deterministický hash pro sloupec original, aby se zabránilo duplicitám logických vazeb. Generuje se automaticky po insertu pomocí triggerů (prefix trgo_), které jsou dynamicky skládány z definic ve sloupci generic_column_list v tabulce meta_object a využívají funkci f_generate_original. U aktivních primárních záznamů platí striktně pravidlo uuid = original. Záznamy přepsané tenantem dědí original ze své předlohy (systém či template).
* Klientský override (Views): Generovaná view (vrepo_{tabname}) automaticky skládají prioritu dat (tenant override > system). Poskytují sloupce:
  - {colname}: finální zresolvovaná hodnota.
  - {colname}_system: vždy původní systémová hodnota 'A' záznamu (dostupné pro VŠECHNY byznysové sloupce pro možnost zjištění odchylky v UI).
  - {colname}_translated: systémový překlad pro aktuální jazyk 'L' (pouze pro překladatelné texty).
  - {colname}_original: 'A' záznam organizace, nebo systémový 'A' záznam (pouze pro překladatelné texty).
  - object_is_mine: příznak (1/0), zda tenant záznam přepsal.
* Ochrana systémových objektů a metadat: Tabulky (např. meta_object, meta_column) využívají sloupce is_final a is_protected k řízení limitů klientského overridu:
  - is_final (bit): 1 = Zcela zakazuje organizacím (tenantům) vytvořit si vlastní přepis záznamu (typ 'A'). Povoluje pouze úpravu jazykových překladů (typ 'L').
  - is_protected (bit): 1 = Povoluje organizaci vytvořit vlastní přepis záznamu (typ 'A'), ale aplikační vrstva (PHP) musí omezit editaci výhradně na vizuální/prezentační vlastnosti (např. caption, helptext, placeholder, sort_code). Technická logika záznamu (např. column_name, input_type, is_computed) zůstává uzamčena (readonly).
* Typy záznamů (record_type): 'A' = aktuálně schválený, 'L' = platná jazyková verze, 'H' = historický záznam (výhradně pro audit).
* Koncepty v SSC (vlastněné uživatelem): 'I' (Insert), 'U' (Update), 'D' (Delete), 'G' (úprava jazykové verze).
* Stavy schvalování (approval_status): Povolené hodnoty řídící SSC jsou 'D', 'W', 'S', 'A', 'R', 'C', 'I'.
* Povinné auditní sloupce jsou date_created, who_created, date_modified, who_modified, language, removed, valid_from, valid_to. Veškeré auditní vazby na uživatele využívají výhradně odkazy typu uuid.

4. Zpracování identit, SSO a multi-tenancy
* Tabulka user_account je globální (object_owner = 0x00). Přihlašovací jméno a e-mail musí být celosystémově unikátní.
* Přístup globálních uživatelů do konkrétních tenantů řídí vazební tabulka user_organization_access (obsahuje is_orgadmin a lokální removed). View v_user_organization_access (s LEFT JOIN na dbsession) sjednocuje čtení oprávnění pro prvotní přihlášení i změnu kontextu.
* Volitelná role: Role v rámci tenanta se pamatuje ve sloupci last_orgadmin. Uživatel, který má statická práva administrátora organizace (is_orgadmin = 1), si může při změně kontextu explicitně vybrat, zda do organizace vstoupí jako Administrátor nebo běžný Uživatel. Volbu zpracovává p_set_login přes parametr @requested_admin a odráží se kompaktně v horním panelu.
* AUTONOMNÍ AUDITNÍ STOPA: Tabulky relací (wwwsession, dbsession) obsahují sloupec user_access_uuid, který nese informaci o konkrétní přístupové vazbě pro aktuální kontext uživatele. Uložené procedury zapisující auditní stopy nesmí přijímat tyto hodnoty jako parametr z PHP. Procedura si musí vždy načíst hodnotu user_access_uuid přímo z tabulky dbsession podle aktuálního @@SPID. To samé platí pro ověřování ochrany proti smazání vlastního účtu.
* SSO integrace a autentizace probíhá plně v PHP vrstvě. Webový server má povolen anonymní přístup. Relaci zakládá T-SQL procedura p_set_login s ohledem na vyžádanou (@requested_org) či poslední navštívenou organizaci (zapisuje do dbsession / wwwsession).
* Přepínání kontextu uživatele (organizace, role) minimalizuje zátěž databáze: řídí se statickým příznakem change_context_allowed. V UI se organizace nepřepíná roletkou v záhlaví, ale výhradně přes dedikovanou stránku (page_change_user_context) formou maticového seznamu s využitím PRG vzoru.
* Pomocná ladicí relace se zakládá přes proceduru p_debuglogin (využívající interně p_set_login a p_init_wwwsession).
* Bezpečnost účtů: Skripty i T-SQL procedury musí vždy obsahovat hard-coded override (nezávislým čtením identity z dbsession), aby uživatel nemohl zrušit svá práva nebo deaktivovat sám sebe. Globální zablokování (inactive) smí provést pouze sysadmin, lokální odebrání přístupu (removed) provádí orgadmin. Filtrování historických/odstraněných záznamů probíhá překreslením na backendu.
* HTTP hlavičky (autoredirect) musí být zasílány jako kompletní string (např. "Location: ...").

5. Architektura UI komponent a kódování stránek
* Abstraktní třídy komponent a základní stavební kameny jsou uloženy s prefixem abstract_. Nové stránky dědí z abstract_page a implementují metodu render_body().
* Tělo stránky (body) má zrušené okraje (margin a padding 0), aby se na něj mohl fixovat obsah bez rušivých mezer.
* Prvek abstract_page_master_detail zajišťuje dynamický dvoupanelový layout přes flexbox s nezávislými V-scrollbary. Podporuje asynchronní refresh levého panelu přes URL parametr ajax_panel=master a nativní Fetch API.
* Klientský frontend využívá výhradně čistý (vanilla) JavaScript (ES6+). Je striktně zakázáno používat jQuery, jQuery UI nebo rozsáhlé frontendové frameworky.
* Formuláře musí být pro dokonalé zarovnání sloučena do jedné HTML tabulky s využitím sjednocených CSS tříd (.md-table, .md-row-active, .md-row-inactive).
* Jmenná konvence stránek je page_{$page}.php a databázové procedury mají názvy page_{$page} a form_{$page}.
* Procedura page_{$page} dodává na stránku všechna potřebná data, prvním parametrem je @subpage, která určuje, která část stránky se má načíst (např. 'main', 'detail' atd.).
* Procedura form_{$page} slouží k zápisu a zpracování formulářů. Prvním parametrem je @subform, který specifikuje operaci zápisu (stisknuté tlačítko apod.).
* Router v index.php podporuje hybridní běh. U objektových stránek instanciuje page_{$page} a volá render(). Autoloader se stará o načítání tříd.
* Globální uživatelský kontext zajišťuje třída user_context implementující __toString(), která vizuálně odděluje globální navigaci (vlevo) a session kontext se zkrácenými formáty rolí (vpravo). 
* Veškeré zpracování POST dat, přesměrování (PRG) a definice UI polí (pageitem) probíhá v konstruktoru třídy stránky (před vykreslováním).
* Přenos dat z databáze do stránek probíhá výhradně voláním uložených procedur.
* Výchozí rozcestník po přihlášení je trvale page_main.php.

6. Stromové struktury, CRMM a Infrastruktura
* Sémantická struktura stromů se udržuje primárně přes relační vazbu parent_uuid. Sloupec sort_code slouží pouze pro rychlé třídění na frontendu.
* Striktní pravidlo uzlů (is_leaf): Aktiva se smí vázat výhradně na koncové uzly (is_leaf = 1).
* Výpočty CRMM: Zbytkové riziko se kalkuluje z hrubého rizika přes redukční a rizikový faktor napojených opatření.
